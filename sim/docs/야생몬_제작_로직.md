# 야생 DB 200체 — 제작 로직 명세 (10-27 밤)

> 망령 지시(10-27 19:13): 「포켓몬 제작이 힘들면 제작 로직에 필요한 것들을 정리해서 문서로 올리고 정지」. 이 문서대로 다른 곳에서 200체를 만들어 `data/wild/db.json` 으로 넣으면, 시뮬 쪽(생성기 연결 · 야생 탭 · 다시 맞추기)은 이어서 붙인다.
> 계산 코드: `sim/lib/pride.js` (제작기 js/maker.js `customCalc` 를 옮김). 도감 · 제외 목록: `sim/lib/dex.js` · `sim/lib/wilddb.js`.

## 1. 망령이 정한 것
| 항목 | 값 |
|---|---|
| 총 수 | 약 200체 |
| 등급 비율 | C : B : A = **7 : 2 : 1** → C 묶음 140 · B 묶음 40 · A 20 |
| 묶음 안 계단 | C 묶음 = C · C+ / B 묶음 = B · B+ / A 묶음 = A (제작기 프라이드 계단) |
| 오리지널 vs 올드 | **오리지널몬이 중심. 올드 타입(실제 포켓몬)은 전체의 2~3할 이하** (200체면 60체 이하) |
| 제작 규칙 | 제작기 「커스텀 포켓몬 계산 종족치」 규칙 그대로 (아래 3절) |

권장 배분 (오리지널 150 + 올드 50):
| | C | C+ | B | B+ | A | 합 |
|---|---|---|---|---|---|---|
| 오리지널 | 63 | 42 | 18 | 12 | 15 | 150 |
| 올드 | 21 | 14 | 6 | 4 | 5 | 50 |
| 합 | 84 | 56 | 24 | 16 | 20 | 200 |

C : C+ = 6 : 4, B : B+ = 6 : 4 는 감우 제안(정해진 것 아님).

## 2. 출력 형식 — `data/wild/db.json`
```json
{
  "v": 2,
  "entries": [
    {
      "id": "w001",
      "origin": "orig",
      "name": "이끼두더지",
      "types": ["땅", "풀"],
      "base": [90, 100, 90, 45, 75, 65],
      "ability": "엽록소",
      "pride": "C",
      "grade": "C",
      "hab": ["숲", "동굴"],
      "role": "일반",
      "moves": [],
      "concept": "젖은 굴에 이끼를 키우는 두더지"
    },
    { "id": "w151", "origin": "old", "sp": "꼬지모", "pride": "C", "grade": "C", "hab": ["숲"], "role": "일반" }
  ]
}
```
- `base` = [HP, 공격, 방어, 특공, 특방, 스피드].
- `pride` = 계단 이름(C · C+ · B · B+ · A), `grade` = 묶음(C · B · A).
- `role`: C 묶음은 「일반」, B · A 는 「보스」 겸용(일반 배틀에도 섞일 수 있음 — 섞는 비율은 시뮬에서 찾는다).
- `moves`: 비워 두면 시뮬이 자동으로 채운다(4절). 직접 넣으면 기술 이름은 제작기 `MKM_DB.moves` 에 있는 이름 그대로.
- `ability`: 제작기 `MKM_DB.abil` 에 있는 이름 그대로(5절).
- 올드 타입은 `sp` 에 제작기 도감(`MKM_DB.old`) 이름만. 타입 · 종족치 · 특성은 도감에서 읽는다.
- 이름은 한국어 오리지널. 실제 포켓몬 · 다른 작품 캐릭터 이름과 겹치지 않게.

## 3. 오리지널몬 프라이드 계산 (제작기 customCalc)
**계산 종족치 = 실제 합 + 하한분 + 내구 할증 + HP 할증 + 화력·스피드 할증 − 쌍두 할인 + 특성 TO 조정**
→ 계산 종족치를 담을 수 있는 가장 낮은 계단이 그 포켓몬의 프라이드.

| 계단 | 통솔점 | 계산 종족치 상한 | 하한(공 · 특공 · 스) | 기준 특성 TO |
|---|---|---|---|---|
| C | 1 | 480 | 40 | 1 |
| C+ | 1.5 | 503 | 43 | 1 |
| B | 2 | 525 | 45 | 1 |
| B+ | 2.5 | 548 | 48 | 1 |
| A | 3 | 570 | 50 | 1.5 |

main = max(공격, 특공), sub = min(공격, 특공). 두 칸 함수 two(x; lo, hi, k1, k2) = k1·(min(x,hi) − lo)⁺ + k2·(x − hi)⁺.

1. **하한분**: 공격 · 특공 · 스피드가 계단 하한보다 낮으면 모자란 만큼 더한다. 주 공격이 아닌 쪽(sub)은 하한을 max(계단 하한, round(main × 0.4)) 로 본다.
   - 예: main 125 → 반대쪽 하한 50. 공격 125 · 특공 40 이면 특공 쪽 +10.
   - 선공 하한: 선공기(우선도 기술) · 선공 특성 · 포텐셜이 있으면 스피드 하한이 더 오른다 → **야생 DB 는 선공기 · 선공 특성을 넣지 않는다.**
2. **내구 할증**: min(방어, 특방) 기준 two(lo 85, hi 105, ×0.5, ×0.75).
3. **HP 할증**: HP 기준 two(lo 95, hi 120, ×0.5, ×0.75).
4. **화력·스피드 할증**: two(main; lo 105, hi 120, ×0.5, ×1) × 스피드 비율. 스피드 비율 = (min(스피드,140) − 90) / 50 을 0~1 로 자름.
5. **쌍두 할인**: 물리기와 특수기를 **둘 다** 가졌을 때만. (min(sub, 120) − 90)⁺ × 1 을 뺀다(최대 30).
6. **특성 TO 조정**: 특성 TO 가 계단 기준 TO 보다 높으면 0.5 당 **+45**, 1 보다 낮으면 0.5 당 **−25** (10-27 개정). 기준과 같으면 0.
7. **제작 조건**: 실제 합 400 이상 · HP · 방어 · 특방 각각 31 이상 · 모든 칸 1~255.

### 맞추는 기준 (감우 제안)
- 계단 「안쪽 끝」에 붙이기: 계산 종족치가 **바로 아래 계단 상한 초과 ~ 그 계단 상한 이하**. (C 는 455~480 권장 — 400대 초반은 약해서 야생 표본이 흐려짐)
- 특성은 기준 TO 와 같은 걸 고르면 조정 0 (C~B+ 는 TO 1, A 는 TO 1.5).

### 예시 (pride.js 로 확인한 줄 — 특성 TO = 기준, 쌍두는 물리 · 특수기 둘 다)
| 계단 | 물리 스위퍼 | 특수 벽 | 밸런스 | 쌍두 |
|---|---|---|---|---|
| C | 75/110/70/40/70/110 (계산 480) | 105/40/85/85/105/50 (475) | 80/85/80/65/80/80 (470) | 75/90/70/90/70/85 (480) |
| C+ | 80/115/70/45/70/115 (499) | 110/45/85/85/110/50 (493) | 85/90/85/70/85/85 (500) | 80/95/70/95/70/90 (495) |
| B | 80/120/75/45/75/120 (523) | 115/45/90/90/115/55 (523) | 90/95/90/70/90/85 (523) | 85/100/75/100/75/95 (520) |
| B+ | 85/125/75/50/75/125 (544) | 120/45/90/90/120/55 (538) | 90/95/90/75/90/90 (533) | 90/105/80/105/80/100 (545) |
| A | 90/125/80/50/80/125 (559) | 125/50/95/95/125/55 (566) | 95/100/95/80/95/95 (565) | 95/105/85/105/85/105 (565) |

(물리 스위퍼의 특공 칸을 낮추면 반대쪽 하한 main×0.4 에 걸려 오히려 손해 — 예시가 그 선에 맞춰져 있다.)

### 확인 방법
```bash
node -e "const P=require('./lib/pride.js');console.log(P.legal([75,110,70,40,70,110]),P.calc([75,110,70,40,70,110],false))"
```
`calc(base, 쌍두여부)` → `{real, ct, step, ok}`. `step` 이 의도한 계단이면 통과. (pride.js 는 특성 TO 조정 · 선공 하한을 안 본다 — 특성은 기준 TO 로 고를 것.)

## 4. 기술 (moves 를 비워 두면)
시뮬 `lib/automove.js` 가 결정적으로 채운다: 공격 ≥ 특공 이면 물리, 아니면 특수 / 자기 타입마다 표준 STAB 1개(위력 70~95) / 견제 1개(효과가 굉장한 칸이 가장 많은 타입). 직접 넣을 때 주의:
- 선공기(우선도 +) 넣지 않기(스피드 하한이 바뀜).
- 물리기 · 특수기를 섞으면 쌍두 할인이 붙는다 → 「쌍두」로 설계한 몬에만 섞기.

## 5. 특성
- 제작기 `MKM_DB.abil` 행 = [TO, 이름, 설명, …]. TO 값 분포: 1 (248) · 1.5 (244) · 2 (197) · 2.5 (101) · 3 (51) · 0.5 (35) …
- C~B+ 는 TO 1, A 는 TO 1.5 특성을 고르면 조정 없음. 더 센 특성(TO 를 올림)을 주면 0.5 당 +45 를 종족치에서 빼서 맞춘다.
- 선공 특성(질풍날개 · 짓궂은마음 류) 피하기.

## 6. 타입 · 서식지
서식지 = 생성기 테마. 타입 하나라도 맞으면 그 서식지에 들어간다(`wilddb.js` HAB).
| 서식지 | 타입 |
|---|---|
| 폐가 | 고스트 · 악 · 독 · 에스퍼 · 노말 |
| 동굴 | 바위 · 땅 · 강철 · 고스트 · 격투 |
| 숲 | 풀 · 벌레 · 독 · 비행 · 노말 · 페어리 |
| 연구소 | 전기 · 강철 · 독 · 에스퍼 · 노말 |
| 유적 | 바위 · 고스트 · 에스퍼 · 땅 · 드래곤 |
| 바다 | 물 · 얼음 · 비행 · 전기 |
| 화산 | 불꽃 · 바위 · 땅 · 드래곤 · 격투 |
| 설원 | 얼음 · 강철 · 페어리 · 물 |

생성기가 테마마다 등급별로 고를 수 있게, **서식지마다 최소 C 묶음 15 · B 묶음 4 · A 2** 체가 걸리도록 타입을 고루 퍼뜨린다(18타입 모두 1체 이상). `hab` 는 타입으로 자동 계산해도 되고, 콘셉트에 맞게 직접 좁혀도 된다.

## 7. 올드 타입 (≤ 2~3할)
- 출처: 제작기 `data/db.js` 의 `MKM_DB.old` (1,240행). 행 = [세대, 이름, 영문, 타입1, 타입2, 특성1, 특성2, 숨특, 알1, 알2, 비고, HP, 공, 방, 특공, 특방, 스].
- 프라이드: **실제 합을 버림한 계단** (480 → C · 503 → C+ · 525 → B · 548 → B+ · 570 → A). 480 미만은 0.5(야생 DB 제외), 600 초과는 EX(제외). 「프렌들리 몬스터」 포텐셜이면 −10.
- 빼는 것: 전설 · 환상 · UB · 패러독스 · 메가 · 거다이맥스 · 원시회귀 · 비고 O(변종). 목록은 `wilddb.js` NOT — **화이트큐레무 · 블랙큐레무가 아직 안 걸러짐**(이름에 「큐레무」 포함으로 고칠 것).
- 일반 A(570~600, 전설 아님)는 12종뿐 → 올드 A 는 5체 정도가 한계.

## 8. 시뮬 쪽에서 남은 일 (DB 가 오면 감우가)
1. `wilddb.full()` 이 오리지널(`origin:'orig'`)을 직접 만들게: `OM_IMPORT.pokemon({id, data:{name, t1, t2, base, ability, item:'', moves, pride, dist:lvAdd, pots:[]}}, 야생트레이너)` → 기술 비면 `automove.fill`. 올드는 지금처럼 `dex.build`.
2. 생성기(`lib/autogen.js`) 풀을 야생 DB 로: 테마 = 서식지, 일반 배틀 · 보스방의 **등급 구성(C/B/A 몇 체)** 을 손잡이로.
3. 다시 맞추기: 쉬움 8할 · 보통 6할 · 어려움 3할이 되는 등급 구성 비율을 찾는다(망령 「어느 정도 강한 몹을 얼마나 배치할지도 규칙 비율」). `autocheck` 로 검증.
4. 야생 탭 UI: DB 표(등급 · 서식지 · 타입 · 이름 필터) + 무리 카드(접기 · 검색해서 추가 · 요약).
5. 문서 갱신: docs/던전_자동생성.md + 공유 문서.
